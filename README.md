# Nova ThinkTank

AI 직원들이 싱크탱크처럼 일하는 로컬 연구 사무실입니다. 사용자가 질문을 던지면 역할이 나뉜 AI 직원
(소장·리서처·레드팀·편집장)이 연구 과정을 거쳐 보고서를 만들고, 그 과정을 평면도 사무실에서 실시간으로 보여 줍니다.

직원은 이 PC에 설치·로그인된 **Claude Code**와 **Codex CLI**로 돌아갑니다(API 키 없음, 각 구독 한도 사용).
로그인 기능 없는 로컬 1인용 앱입니다.

> 현재 단계: **M1b(재반박) + M3** — 웹 사무실에서 연구소를 만들고, 질문을 맡기고, 직원이 무엇을 하는지 보고, 보고서를 읽고 사후 검토를 남깁니다.
> 기획안: [`docs/plan.md`](docs/plan.md) · M0 검증: [`spikes/m0/RESULTS.md`](spikes/m0/RESULTS.md) · 검토 기록: [`docs/reviews/`](docs/reviews/)

## 연구 흐름

```
소장(Claude)        질문을 다듬고 리서처마다 관점·하위 질문 배정 (질문을 읽을 수 없으면 추측하지 않고 멈춤)
  ↓
리서처 A(Claude) ┐  웹 검색으로 조사, 주장마다 근거(출처·발행일·확인일·구절)와 근거/추론 구분
리서처 B(Codex)  ┘  필요하면 사내 메신저(MCP)로 서로 질문 → 답을 받아 메모 수정
  ↓
레드팀(Codex)       1단계: 리서처 결론을 보기 전에 출처만 평가
                    2단계: 주장을 공격하고 "결론이 틀리는 조건"을 씀
  ↓
재반박              반론이 겨냥한 주장의 주인이 수용 / 부분 수용 / 거부(출처 필수)로 답함 (회의 테이블)
                    심각도 high·결론 영향인데 리서처가 버틴 반론만 레드팀이 한 번 더 답함 (최대 2라운드)
  ↓
편집장(Claude)      모든 반론에 반론 유지 / 재반박 인정 / 미해결(풀릴 조건 필수) 판정, 발견 · 이견 · 행동 제안(거시/개인) · 미해결 질문
```

## 원칙

- 보고서에는 "결론" 섹션이 없습니다. **사용자의 가설 → 발견 → 이견 → 레드팀 반론과 응답 → 행동 제안 → 미해결 질문 → 근거 → 사후 검토** 순서입니다.
  AI의 답을 그대로 받아들이지 않게 하려는 장치입니다.
- 맡기기 전에 사용자의 예상을 먼저 묻고(건너뛸 수 있음), 보고서를 읽은 뒤 사후 검토를 남기게 합니다.
- 직원 권한은 프롬프트가 아니라 실행기가 강제합니다:
  - Claude: 내장 도구는 `WebSearch`·`WebFetch`만, `--strict-mcp-config`(사용자의 claude.ai 커넥터 차단), 사용자 설정·스킬 제외
  - Codex: `--ignore-user-config`, 읽기 전용 샌드박스, 셸·브라우저·컴퓨터 사용 등 기능 끔
  - 사내 메신저(MCP)는 실행 중인 자기 턴에서만, 같은 연구의 리서처에게만, 연구당 2개까지
- 산출물마다 스키마와 참조(주장 ID 등)를 서버가 검증하고, 실패하면 고쳐 달라고 다시 묻습니다.
- 반론-재반박은 최대 2라운드입니다. 연구들이 효과는 1~2라운드에서 대부분 나오고, 더 늘리면 비용과 동조만 커진다고 보기 때문입니다
  ([`docs/reviews/2026-10-17_m1b-rebuttal.md`](docs/reviews/2026-10-17_m1b-rebuttal.md)). 편집장이 반론을 90% 넘게 유지하면 보고서에 경고가 붙습니다.

## 요구 사항

- Windows 11에서 검증 (macOS·Linux는 미검증)
- Node.js 22 이상
- Claude Code, Codex CLI — 설치하고 로그인한 상태

## 사무실 열기

```bash
npm install
npm run office          # http://127.0.0.1:4317 (화면을 빌드한 뒤 연다)
npm run office:dev      # 화면 코드를 고치며 볼 때 (Vite가 바로 반영)
```

- **로비**: 연구소(주제별 묶음)를 만들고, 질문과 "내 예상"을 적어 연구를 맡깁니다.
- **연구 화면**: 평면도에서 직원이 일하는 모습(점선 고리 = 일하는 중, 쪽지 = 지금 하는 일, 형광펜 = 검색·읽기·질문,
  동료에게 물으면 그 자리로 걸어감), 화이트보드의 단계 진행, 오른쪽 활동 기록, Claude 사용 한도.
  직원을 누르면 그 사람의 기록만 봅니다. 연구마다 따로 멈추고 이어서 할 수 있습니다.
- **아래 탭**: 진행 중인 자료(연구 설계·리서치 메모·레드팀 출처 평가와 반론), 보고서, 사후 검토. 사후 검토를 저장하면 보고서 파일에도 들어갑니다.
- **보고서 형식**: 같은 내용을 `.md`(Obsidian, 긴 부분은 접기 콜아웃)와 `.html`(브라우저, 앱 보고서 탭)로 함께 저장합니다.
  순서는 내 예상 → 한눈에 보기(결론이 아닌 지도: 발견별 근거 강도·가장 큰 불확실성·지금 할 일) → 핵심 발견 → 행동 제안
  → 이견과 미해결 → 검증 기록(접힘) → 부록(접힘) → 사후 검토. "근거 신호"는 리서처 모델의 확신도에서 출발해
  본문 미확인·주장 수정·낮은 출처 신뢰도·핵심 반론 유지/미해결로 낮추는 참고 지표입니다(사람의 검증이 아닙니다).
- 보고서를 볼트 같은 다른 폴더에도 저장하려면 저장소 루트에 `nova.config.json`(Git 제외)을 둡니다: `{ "exportDir": "C:/.../보고서" }`
- 앱은 `127.0.0.1`에서만 열리고, 다른 사이트에서 온 요청은 거절합니다(로그인이 없으므로).

## 터미널에서 쓰기

```bash
npm run study -- "질문"                          # 시작 (내 예상을 먼저 묻는다)
npm run study -- "질문" --hypothesis "내 예상"    # 예상을 인자로
npm run study -- "질문" --export-dir <폴더>       # 보고서를 다른 폴더(예: Obsidian 볼트)에도 저장
npm run study -- --list                         # 연구 목록과 상태
npm run study -- --resume <studyId>             # 멈춘 연구 이어서
```

- **Ctrl+C** 한 번: 진행 중인 턴을 끝내고 저장한 뒤 멈춥니다(`paused`). 두 번: 즉시 종료.
- **한도**: Claude 5시간 한도 사용률이 90%를 넘거나 한도 오류가 나면 `waiting_limit`으로 멈춥니다. 재시도를 반복하지 않습니다.
- **이어서 실행**: 단계별 산출물이 체크포인트입니다. 끝난 단계는 다시 돌지 않습니다.
- 데이터는 `data/`(Git 제외)에 있습니다: `nova.db`(SQLite), `studies/<id>/report.md`, 직원 작업 폴더.
- 같은 연구를 사무실과 터미널에서 동시에 돌릴 수는 없습니다(잠금).

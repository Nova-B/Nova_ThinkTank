## 1. 무엇을 만드는가

**AI 직원들이 연구소처럼 일하는 로컬 웹앱.** 사용자가 탐구 주제(ThinkTank)를 만들고 질문을 던지면, 역할이 나뉜 AI 직원들이 싱크탱크의 연구 과정을 거쳐 보고서를 만든다. 그 과정은 사무실 화면에서 실시간으로 보인다.

싱크탱크 사고 5단계(참고: ChatGPT 대화 "AI 시대 전략 제안")를 그대로 작업 흐름으로 쓴다.

1. **질문 설정** — 앞으로 무엇이 중요해질까?
2. **자료 조사** — 어떤 근거가 있는가?
3. **시스템적 사고** — 다른 분야에 어떤 영향을 주는가? (기술·경제·에너지·사회 등 분야별)
4. **시나리오 분석** — 내 예상이 틀리면 어떤 일이 생기나? (빠른 성장 / 점진 / 병목)
5. **행동 도출** — 지금 무엇을 준비해야 하나?

### 핵심 개념

| 개념 | 뜻 |
| --- | --- |
| **ThinkTank (연구소)** | 주제 하나에 대한 상설 연구 공간. 예: "AI와 에너지", "한국 인구 2040". 여러 개를 만들 수 있다 |
| **Study (연구 과제)** | ThinkTank 안에서 질문 하나를 끝까지 돌리는 한 번의 실행. 결과는 보고서 1편 |
| **Employee (직원)** | 역할 + 엔진(claude/codex) + 모델 + 성격 지침. **직원은 정의일 뿐이고, CLI 세션은 Study마다 새로 연다**(직원 × Study = 세션 1개). 다른 연구의 맥락이 섞이지 않게 하기 위해서다 |
| **Stage (단계)** | 위 5단계 + 반론 검토 + 편집. 단계마다 담당 직원과 산출물이 정해져 있다 |
| **Artifact (산출물)** | 단계별 메모, 출처 목록, 시나리오 표, 최종 보고서(Markdown) |

## 2. 사무실 구성 (기본 직원 명단, ThinkTank마다 바꿀 수 있음)

| 역할 | 엔진(기본) | 하는 일 |
| --- | --- | --- |
| 소장 (Director) | Claude | 질문을 다듬고 하위 질문으로 쪼갠 뒤 분야 리서처에게 배분, 단계 전환 결정 |
| 분야 리서처 ×2~4 | Claude / Codex 섞어서 | 맡은 분야(기술·경제·에너지·사회 등) 자료 조사와 분석, 출처 기록 |
| 시나리오 플래너 | Claude | 리서치를 묶어 시나리오 3개와 각 시나리오의 조건·신호(early signal) 정리 |
| 레드팀 | **Codex** (다른 모델) | 가정 공격, 반대 근거, "이 결론이 틀리는 조건" 작성. 엔진이 다르다고 독립적인 판단이 보장되지는 않으므로, **초안을 보기 전에 원자료를 먼저 평가하고** 그다음 초안과 비교한다 |
| 편집장 | Claude | 최종 보고서 작성. 합의 사항·이견·미해결 질문을 나눠 적는다 |

직원끼리는 앱이 띄우는 로컬 MCP 서버의 `ask_colleague`, `post_note`, `read_notes` 같은 도구로 소통한다.

- `ask_colleague`는 **비동기 큐**다. 호출하면 요청 ID를 바로 돌려주고, 답은 상대 직원의 다음 턴에서 만들어져 질문한 직원의 다음 턴에 전달된다. 동기로 기다리면 실행 슬롯 2개가 서로의 답을 기다리며 멈출 수 있다(교착).
- crew-office 스파이크는 MCP 연결과 긴 대기만 검증했다. 그때 MCP 서버는 가짜 답을 돌려줬으므로 **실제 직원 간 왕복은 아직 검증되지 않았다** → M0에서 확인한다.

## 3. 모델교 방지 장치 (볼트 CLAUDE.md §0.5를 제품에 넣는다)

이 앱이 "AI가 결론을 내주는 기계"가 되면 볼트의 운영 철학과 정면으로 부딪친다. 그래서 다음을 **기능으로** 넣는다.

- **사전 가설 입력** — Study를 시작할 때 사용자가 먼저 "내 예상"을 한 줄 적는다(건너뛸 수는 있지만 기본으로 묻는다). 보고서 맨 앞에 그대로 실린다.
- **레드팀 필수 단계** — 반론 단계는 건너뛸 수 없다.
- **보고서 고정 양식** — `🪞 Nova의 가설` → 핵심 발견 → 시나리오 → 이견(직원 간 불일치) → 행동 제안 → `❓ 미해결 질문` → 출처. "결론" 섹션 대신 "이견"과 "미해결"을 반드시 둔다.
- **주장 단위 근거** — 주장마다 근거 구절, 출처 URL, 발행일, 확인일, `근거 / 직원 추론` 구분을 함께 저장한다. URL만 붙여서는 검증할 수 없기 때문이다.
- **사후 검토** — 보고서 끝에서 사용자에게 "가설과 무엇이 달랐나?"를 묻고, 답을 보고서에 덧붙인다.
- 볼트로 내보낼 때는 `checked: false`로 저장한다.

## 4. 시각화 — "AI가 지금 무엇을 하는지" 보이게

| 화면 | 내용 |
| --- | --- |
| **사무실 뷰** | 2D 탑다운 사무실(Canvas). 직원마다 책상, 상태 아이콘과 말풍선(생각 중 · 웹 검색 중 · 문서 읽는 중 · 작성 중 · 동료에게 질문 · 대기 · 오류). `ask_colleague`가 일어나면 직원이 상대 자리로 걸어가고, 레드팀 토론은 회의실에서 열린다 |
| **화이트보드** | 사무실 벽에 현재 Study의 단계 진행률(5단계 + 반론 + 편집) |
| **활동 피드** | 오른쪽 패널. CLI JSON 이벤트를 정규화한 실시간 로그(도구 이름, 검색어, 읽은 URL, 소요 시간) |
| **산출물 패널** | 단계별 메모와 최종 보고서 미리보기 |
| **ThinkTank 로비** | 연구소 목록, Study 이력, 직원 명단 편집 |

**결정 필요:** MVP는 2D Canvas로 가볍게 가고, 3D(three.js)는 나중 선택지로 둘지. DeskRPG처럼 3D로 처음부터 갈지.

## 5. 기술 구조 (제안)

```
Nova_ThinkTank/
├─ server/                 Node 22 + TypeScript
│  ├─ runner/              CLI 실행기 (claude, codex) — 셸 없이 실제 실행 파일 spawn
│  │  ├─ claude.ts         stream-json 이벤트 → 공통 이벤트
│  │  └─ codex.ts          exec --json 이벤트 → 공통 이벤트
│  ├─ orchestrator/        Study 상태 기계: 단계 전환, 직원 배정, 동시 실행 제한, 재시도
│  ├─ mcp/                 직원용 로컬 MCP 서버 (ask_colleague, post_note, read_notes)
│  ├─ store/               SQLite: thinktanks, employees, studies, stages, events, artifacts
│  ├─ notify/              알림 채널 인터페이스 (지금은 콘솔/파일, 나중에 카카오·텔레그램)
│  └─ http.ts              REST + WebSocket(실시간 이벤트)
├─ web/                    Vite + React, 사무실 Canvas 렌더러
├─ data/                   (gitignore) DB, 직원 작업 폴더, 보고서
└─ docs/
   ├─ plan.md              이 기획안의 코드 저장소용 사본
   └─ reviews/             Codex와 주고받은 검토 기록
```

### 공통 이벤트 모델 (시각화의 원천)

```ts
type EmployeeEvent =
  | { kind: "turn_started"; employeeId; stage }
  | { kind: "thinking" }
  | { kind: "tool_use"; tool: string; summary: string }   // WebSearch "AI 전력 수요 2035" 등
  | { kind: "text_delta"; text: string }
  | { kind: "ask_colleague"; to: string; question: string }
  | { kind: "turn_completed"; usage?; costEstimateUsd? }
  | { kind: "turn_failed"; reason: string };
```

### crew-office 0단계 스파이크에서 가져올 사실 (코드가 아니라 검증된 지식)

- Claude: `claude -p --output-format stream-json --verbose`, 세션 ID는 `system/init` 이벤트, 이어가기는 `--resume`. **작업 폴더가 세션 키의 일부라** 직원 폴더를 고정해야 한다.
- Codex: `codex exec --json -`, 세션 ID는 `thread.started`, 이어가기는 `codex exec resume <id>`. MCP 도구는 `approval_mode="approve"`를 줘야 exec 모드에서 실행된다.
- Windows에서 `spawn("claude")`는 ENOENT/EINVAL로 실패한다. 실제 실행 파일(`claude.exe`, `node codex.js`)을 찾아 직접 띄운다.
- `HOME`을 바꾸면 로그인이 깨진다. 격리는 작업 폴더와 권한 모드로 한다.
- 현재 버전(Claude Code 2.1.302, codex-cli 0.163.0)은 스파이크 당시(2.1.280 / 0.156.1)보다 새것이라 **이벤트 모양을 다시 확인**해야 한다.

- Codex 0.163.0에는 로그인은 유지하고 사용자 설정(`~/.codex/config.toml`의 다른 MCP 등)은 빼는 `--ignore-user-config`가 있다. 기본으로 쓰되, 프로젝트 지침까지 모두 격리된다고 가정하지 않는다.
- 단계 산출물은 자유 텍스트 대신 **구조화된 출력**으로 받는다(Codex `--output-schema`, Claude는 JSON 스키마 지침 + 서버 검증).
- 공통 이벤트 모델은 `text_delta`가 항상 온다고 가정하지 않는다. Codex의 `item.*` 이벤트, 오류 이벤트, 종료 코드를 모두 처리한다.
- MCP 도구 승인(`approval_mode="approve"`)은 허용할 도구에만 하나씩 지정한다.

### 오케스트레이션 규칙

- **단계 전환은 소장이 제안하고 서버가 확정한다.** 서버는 그 단계의 산출물이 스키마를 통과했는지 확인한 뒤에 다음 단계로 넘긴다.
- 실행 상태: `대기 → 실행 → (한도 대기) → 완료 / 실패 / 취소`, 재시도 횟수를 기록한다.
- 레드팀 반론이 받아들여지면 **행동 제안 단계로 되돌아가는 경로**가 있다.
- 같은 세션에서 두 턴을 동시에 돌리지 않는다.
- 세션 ID는 턴이 시작되자마자 실행 기록에 저장하고, 성공 여부는 따로 기록한다. 단계별 체크포인트와 중복 저장 방지 키를 두고, 앱을 재시작하면 미완료 턴을 판정해 이어 가거나 다시 돈다.
- Windows에서 취소할 때는 CLI가 띄운 자식 프로세스(MCP 서버 등)까지 함께 종료한다.

### 안전·사용량

- 앱은 `127.0.0.1`에만 바인딩하고 WebSocket·REST 요청의 Origin을 검사한다(로그인이 없어도 다른 웹페이지가 로컬 앱을 조작하지 못하게).
- 직원 권한은 프롬프트로 부탁하지 않고 **실행기와 MCP 서버가 강제한다**: 읽기 전용 샌드박스, 웹 검색·가져오기만 허용. 보고서·메모 저장은 직원이 아니라 앱이 한다.
- 상한은 여러 겹으로 둔다: 엔진별 동시 실행 수(기본 각 1~2), Study별 호출 수·총 시간·토큰, 직원 간 `ask` 깊이·횟수, **모두 멈추기** 버튼.
- 구독 잔여량은 토큰으로 정확히 환산할 수 없다. 한도에 걸리면 재시도를 반복하지 않고 `한도 대기` 상태로 멈춘 뒤 사용자에게 알린다.
- Claude는 `total_cost_usd` 추정치를 보여 주고(실제 청구액 아님), Codex는 토큰 수만 보여 준다.

4. 첫 Study 주제: **"AI 시대, 앞으로 거시적으로 중요한 것(에너지, 보안, 우주 등)과 미시적으로 개인이 할 수 있는 일은 무엇인가 — 충분히 숙고하고 제안"** (원문의 "보완"은 "보안"으로 읽음, 확인 필요)
